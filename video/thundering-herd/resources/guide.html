The Thundering Herd Problem

What happens when ten thousand requests hit an empty cache at once

Ever wonder what happens when your cache entry expires at the exact same moment ten thousand requests hit your server? That's the thundering herd problem — a simple timing coincidence that can turn a quiet database into an overloaded one in an instant.

What Triggers It

It starts with one cache key expiring. Every request that needed that data suddenly finds it missing, all at once. So all ten thousand requests go straight to the database to recompute the same value.

Why It Hurts

Your database, which was handling light load a second ago, just got hit with ten thousand queries at the same time — all asking for the exact same piece of data, all landing in the same instant.

The Fix: Request Coalescing

The fix is simple. Only one request is allowed to recompute the value. Every other request waits for that result, then reads it from cache.

This is usually called request coalescing, or a distributed lock around the recompute step.

Key Takeaways

  • A single cache key expiring can cause every dependent request to miss at once.
  • Without protection, all of those requests hit the database simultaneously to recompute the same value.
  • The fix: let one request recompute while the rest wait and then read from cache.
  • This pattern is known as request coalescing, or a distributed lock around the recompute step.
