Signal Path: companion guide

Vertical, horizontal, and auto-scaling

Three separate decisions, and only one of them is really about automation.

"We need to scale" gets treated like a single decision, but it's actually three independent ones. Vertical scaling and horizontal scaling are two different ways to get more capacity. Auto-scaling isn't a third way to get capacity at all: it's the automation layer that decides when to use the other two. This guide walks through each one on its own, then lays out a simple order for adopting them.

01 · Vertical scaling

One machine, bigger

Vertical scaling means making one machine bigger: more CPU, more RAM, on the same box.

It's the simplest option. Nothing about your architecture has to change. But it has a limit: you eventually hit a hardware ceiling, and there's still just one machine that can go down.

02 · Horizontal scaling

More machines, side by side

Horizontal scaling means adding more machines instead, running the same service side by side.

There's no hard ceiling the way vertical scaling has, and you get redundancy for free: if one instance dies, the others are still there.

The tradeoff: your app has to be built to run as multiple, coordinated copies.

03 · Auto-scaling

The automation layer, not a third option

Auto-scaling isn't a third way to add capacity: it's the automation layer on top of the other two.

It watches real demand and adds or removes capacity for you, instead of a human deciding when to scale up or down.

Capacity vs. decision

Where each of the three actually sits in the decision.

The split

Vertical and horizontal scaling both answer how do we get more capacity.

Auto-scaling answers a different question: who decides when we need it, and how fast do we react.

Which one, when

A simple order to adopt them in, cheapest and simplest first.

  1. Scale vertically first: it's the cheapest fix while you're small.
  2. Move to horizontal once you need redundancy, or you're hitting the ceiling of a single machine.
  3. Add auto-scaling once your traffic is unpredictable enough that manual scaling can't keep up.
Key takeaways
  • Vertical scaling is one machine getting bigger: simple, but capped, and still a single point of failure.
  • Horizontal scaling is many coordinated machines: no hard ceiling, redundancy for free, but it requires code built to run as multiple copies.
  • Auto-scaling is the decision layer, not a capacity mechanism: it automates when to reach for vertical or horizontal capacity.

Scale vertically first, go horizontal for redundancy or ceiling, add auto-scaling only once traffic outpaces manual decisions.
